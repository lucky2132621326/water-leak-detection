# DATABASE SCHEMA

Database Engine: **MongoDB** (`mongodb://localhost:27017/water_leak_detection`)

## Collections & BSON Schemas

### 1. `telemetry` (Collection)
Stores 1Hz sensor readings from physical rig or simulated MQTT publisher.
```json
{
  "_id": "ObjectId(...)",
  "ts": 1754131200,
  "seq": 1042,
  "q_in_lpm": 4.50,
  "q_out_lpm": 4.40,
  "q_branch_lpm": 0.00,
  "current_ma": 830.0,
  "voltage_v": 11.9,
  "pressure_bar": 2.45,
  "raw_pulses_in": 4560,
  "raw_pulses_out": 4480,
  "solenoid_state": 0,
  "created_at": "2026-08-03T09:45:00.000Z"
}
```
**Indexes**:
- `{ ts: -1 }` (Descending timestamp index for fast 1Hz range scans)

---

### 2. `leak_events` (Collection)
Ground truth records of injected leaks during experimental test runs.
```json
{
  "_id": "ObjectId(...)",
  "start_ts": 1754131260,
  "stop_ts": 1754131285,
  "location_node": "Branch_A (Side Loop Node 3)",
  "severity_lpm": 1.25,
  "is_ground_truth": true,
  "notes": "Manual solenoid valve open injection test"
}
```

---

### 3. `detections` (Collection)
Alert outputs generated by multi-method detection algorithms and sensor fusion.
```json
{
  "_id": "ObjectId(...)",
  "ts": 1754131262,
  "method": "Mass Balance Residual (3-Sigma)",
  "confidence": 0.94,
  "residual": 1.23,
  "is_alarm": true,
  "leak_event_id": "ObjectId(...)"
}
```
**Indexes**:
- `{ ts: -1 }`
- `{ is_alarm: 1, ts: -1 }`

---

### 4. `experiment_runs` (Collection)
Metadata for benchmark replay datasets (`RUN_001` - `RUN_012`).
```json
{
  "_id": "RUN_001",
  "operator": "Manoj",
  "date": "2026-08-03",
  "leak_size_lpm": 0.50,
  "leak_location": "Branch_A",
  "pump_mode": "constant",
  "notes": "Micro-leak sensitivity baseline test"
}
```

---

### 5. `work_orders` (Collection)
Field repair crew work orders generated by CP-SAT optimization.
```json
{
  "_id": "WO-2026-001",
  "leak_event_id": "ObjectId(...)",
  "location_node": "Branch_A (Side Loop)",
  "severity_lpm": 1.25,
  "priority": "HIGH",
  "assigned_crew": "CREW_ALPHA",
  "scheduled_start": "2026-08-03T11:00:00.000Z",
  "estimated_hrs": 1.8,
  "status": "DISPATCHED"
}
```

### 6. `alerts` (Collection)
Operator-facing leak incidents, aggregated from per-sample detection responses
by `backend/alerts/alert_service.py`. One incident spans many alarm samples —
see `docs/IMPACT_AND_ALERTS.md` for the merging and lifecycle rules.

Note `is_open` (the detector currently sees the anomaly) is distinct from
`status` (the operator's disposition): an incident whose alarm has cleared stays
`ACTIVE` until someone verifies or repairs it.

```json
{
  "alert_id": "LEAK-0001",
  "seq": 1,
  "source": "replay",
  "run_id": "RUN_001",
  "status": "ACTIVE | RESOLVED | FALSE_POSITIVE",
  "is_open": false,
  "zone": "Branch_A",
  "confidence_tier": "HIGH",
  "likelihood_score": 41.0,
  "start_ts": 1785945590,
  "last_seen_ts": 1785945637,
  "end_ts": 1785945637,
  "duration_sec": 47.0,
  "sample_count": 48,
  "leak_rate_lpm": 1.25,
  "peak_leak_rate_lpm": 1.25,
  "evidence": "flow residual +1.25 L/min (above baseline); ...",
  "active_methods": ["current_signature", "cusum"],
  "false_positive_warning": { "disclaimer": "...", "estimated_false_positive_rate": 0.03 },
  "work_order_summary": { "summary": "...", "source": "template | llm" },
  "impact": { "severity": "CRITICAL", "litres_per_day": 1800.0, "cost_per_year": 13140.0, "...": "..." },
  "created_at": 1785945650.12,
  "resolved_at": null,
  "resolution_note": null,
  "water_saved_litres": 0.0,
  "cost_saved": 0.0
}
```
Indexed/queried by `alert_id`; `water_saved_litres` and `cost_saved` are only
non-zero once `status` is `RESOLVED`.

### 7. `events` (Collection)
Operational event log written by `backend/services/event_logger.py` — actuator
toggles, calibration runs, detector alarms. Previously undocumented here.
```json
{
  "ts": 1785945650.12,
  "category": "ACTUATOR | CALIBRATION | DETECTOR",
  "message": "Solenoid valve 2 opened",
  "metadata": {}
}
```
`metadata` is free-form and category-dependent.
